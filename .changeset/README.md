# Changesets — JS/TS release automation

This directory drives versioning and publishing for the **npm packages** in the
bun workspace (`node/*`), the JS-side counterpart to what
[`release-plz`](../release-plz.toml) does for the Rust crates.

## How it works here (automatic, from commits)

You normally **do not** hand-write changeset files. On every push to `main`, the
`version-pr` job in [`js-release`](../.github/workflows/js-release.yaml) reads the
merged conventional commits that touched `node/**` and derives the `.changeset/*.md`
entries for you (mapping commit `scope` → package, commit type → bump level). It
carries those entries — plus the version bumps and per-package `CHANGELOG.md` —
onto a single long-lived **"Version Packages" PR** (the Changesets action's
`changeset-release/main` branch). **Nothing is committed to `main`**: the pending
release state lives on that PR, exactly like release-plz's Release PR. Merging it
lands the bumps and (when publishing is enabled) triggers the NAPI build + npm
publish.

## When to add a changeset by hand

Run `bun run changeset` and commit the generated file when the automatic mapping
is not what you want:

- a **breaking change** that must be an explicit `major` with a migration note;
- a package that needs a **different bump** than its commit type implies;
- a **cross-cutting** change where you want to describe the release note yourself.

A hand-written changeset for a package **wins** over the autogenerated one for the
same package in the same batch, so adding one is always safe.

See [`.agents/rules/js-release-changesets-rule.mdc`](../.agents/rules/js-release-changesets-rule.mdc)
for the full agent contract.

## Current state: DORMANT

Publishing is **gated off** until the publish scope is decided (see the
dependency-isolation / publish-scope follow-up). While the `JS_PUBLISH_ENABLED`
repo variable is unset or not `"true"`, the NAPI build matrix and publish job
**do not run at all** — only the version-PR job runs, so no multi-arch build or
npm publish happens on any push. Only `@open-lakehouse/uc-client` (+ its platform
packages) is currently non-private; every `@open-lakehouse/*` package is
`private: true` and Changesets skips it.

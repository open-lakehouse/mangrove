# olai-uc-handlers

**The Unity Catalog handler traits, one per service and gated per resource, so a
service can implement just the resources it serves without depending on the
whole server.**

> [!NOTE]
> The Rust crate identifier is `unitycatalog_handlers` (imports and paths use
> that name); the crate is published to crates.io as `olai-uc-handlers` while
> the naming settles. This is an experimental component of an unofficial
> [Unity Catalog](https://unitycatalog.io) implementation.

Each Unity Catalog service has a generated async trait with one method per RPC
(`CatalogHandler`, `CredentialHandler`, `ExternalLocationHandler`, …). With the
`axum` feature, each service also has a `server` module of axum route functions
that extract the request, call the trait, and serialize the response. The crate
also carries the types those traits name: the `Error` / `Result` they return and
the default request context, `RequestContext` (the caller's `Principal`).

`olai-uc-server` implements these traits on top of a `ResourceStore` and a
`Policy`. A standalone service, such as an Open Sharing server that only needs
credentials and external locations, can depend on this crate with just those
features and implement the traits over its own storage.

## Usage

```toml
[dependencies]
unitycatalog-handlers = { package = "olai-uc-handlers", version = "0.0.1", default-features = false, features = ["credentials", "axum"] }
```

```rust,ignore
use axum::routing::get;
use unitycatalog_common::models::credentials::v1::*;
use unitycatalog_handlers::credentials::{CredentialHandler, server};
use unitycatalog_handlers::{RequestContext, Result};

#[derive(Clone)]
struct MyBackend;

#[async_trait::async_trait]
impl CredentialHandler for MyBackend {
    async fn get_credential(&self, request: GetCredentialRequest, cx: RequestContext) -> Result<Credential> {
        todo!()
    }
    // …
}

let router = axum::Router::new()
    .route("/credentials/{name}", get(server::get_credential::<MyBackend, RequestContext>))
    .with_state(MyBackend);
```

`RequestContext` reads the `Principal` that an authentication middleware put
in the request extensions and falls back to anonymous. To authorize against your
own context type, implement the trait as `CredentialHandler<MyCx>` and give `MyCx`
an axum `FromRequestParts` impl.

## Feature flags

| Feature | Enables |
| --- | --- |
| `all-resources` (default) | every resource below |
| `agent_skills`, `agents`, `catalogs`, `credentials`, `external_locations`, `functions`, `model_versions`, `policies`, `providers`, `recipients`, `registered_models`, `schemas`, `shares`, `staging_tables`, `tables`, `temporary_credentials`, `volumes` | that service's handler trait, plus the same-named `olai-uc-common` model feature |
| `tags` | the entity-tag-assignment and tag-policy services (both built on the `tags` models) |
| `axum` | the `server` route functions, `IntoResponse` for `Error`, `FromRequestParts` for `RequestContext` |
| `object-store`, `store`, `cloud` | `Error` variants and `From` impls for `object_store`, `olai-store` and `olai-http` errors |

## Generated code

Everything under `src/codegen/` is generated by `just generate-code` (trestle,
configured in `trestle.yaml` under `generate.server`) and must not be edited by
hand. `src/lib.rs` mounts each service behind its feature. A drift test fails
when a regeneration adds a service that `lib.rs` doesn't mount yet.
